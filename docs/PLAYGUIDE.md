# SUNRISE LAB 操作ガイド

実装済みの日本語・高校生モード向けPCブラウザーゲームです。マウスだけで操作できます。画像・フォントの外部取得や実行時API通信はありません。ドラッグ＆ドロップは使わず、部品のクリック選択→配置で組み立てます。

## 起動とビルド

依存パッケージがローカルキャッシュにあるこの作業環境では、次のオフラインインストールを確認しました。

```powershell
npm.cmd ci --offline --cache .npm-cache --no-audit --no-fund
npm.cmd test
npm.cmd run validate
npm.cmd run build
npm.cmd run dev -- --host 127.0.0.1 --port 4173
```

PowerShellの実行ポリシーがnpm.ps1を止める環境ではnpm.cmdを使います。5173番はこの環境でEACCESになったため4173番を指定します。配布用ファイルはdist/です。Vite baseは './'、dist/.nojekyllを生成します。GitHub Pagesにはdist/の内容を配置します。実際のGitHub Pagesへのデプロイは未確認です。

## 1 — どうして薬が効かないの？

「抗生物質を投与する」をクリック。計算パネルの後、細菌の図、細胞数、log10 Nの曲線が同じモデル結果から再生されます。右側には細胞の模式図、KanRによるリン酸化の説明、Exp3の測定IC50点（SD付き）とモデルMIC曲線があります。測定とモデルは別の評価指標であること、高発現域のプラトーをモデルが再現しないことを明記しています。

3択問題は何度でも答え直せます。正解は「細菌がKanRという酵素を作り、カナマイシンを化学的に変化させて無力化しているから」。回答を選んだ後の「次へ」で組み立てに進みます。18時間分の再生終了を待つ必要はありません。

## 2 — SUNRISEを組み立てよう！

各部品ボタンをクリックし、その部品に対応する「配置先」ボタンをクリックします。選択中の部品は紫の枠で示します。配置済み部品も同じ手順で交換できます。

| スロット | 成立する部品 |
| --- | --- |
| Pvc13のRBP | gp17（大腸菌LPS） |
| 注入装置 | PVCコア（鞘・内管） |
| 運ぶタンパク質 | TPDアダプター |
| 積み込みの荷札 | Pdp1 N末端 |
| Binder | KanR用Binder |
| Linker | 柔軟なGGS Linker |
| Anchor | XB（ClpX ZBD結合） |

未配置のスロットは中立の案内だけを表示します。部品を配置するとPVC（基盤・RBP尾繊維・鞘・内管・内部の荷物）とBinder / GGS Linker / XBの図が順に組み上がります。誤った部品や部品なしも配置できます。黄色のスロットと説明文はmodel/evaluateBuildのFailureReasonに由来します。「ステージ3へ」は誤構成でも押せます。「試してみる」を選ぶと失敗過程を観察でき、「直す」を選ぶとその場で交換できます。

## 3 — SUNRISEを起動！

初期MOIは30。スライダーは1〜30で、変更すると前処置モデルを再計算し、タイムラインを先頭に戻します。λ、P(j=0)、代表注入回数、平均N_tot、平均KanR B、平均遊離ClpXP、平均量から評価したk_effを表示します。代表jは平均注入回数の丸めで、全細胞に同じ注入回数を与えているという意味ではありません。シミュレーション内部はPoissonの各注入クラスを保持します。

「SUNRISEを起動」で約22秒の単一タイムラインを再生します。7段階のリストは現在の段階を強調表示します。一本のスクラバーで前後へ移動でき、一時停止・再生・「もう一度見る」があります。KanR曲線にはB0の基準線があります。

誤ったRBPは付着段階（約3.1秒）、装置・荷札・荷物の不備は注入段階（約6.3秒）、誤Binderは認識段階（約9.4秒）、Linker・XBの不備は複合体形成段階（約12.6秒）で停止します。説明を読んで「組み立てに戻る」から交換します。

正しい構成で最後まで進むと比較ボタンが有効になります。MOI30でほぼ完全な到達になることはモデル予測として明示しています。20個の到達図は期待個数を丸めた模式表示で、MOI30では灰色0個、MOI1では灰色7個です。小さい未到達確率そのものは数値で読み取れます。

## 4 — もう一度、抗生物質を使ってみよう！

SUNRISEあり・なしの2本を同じモデルで計算し、フレームをキャッシュして再生します。1秒で約30分、速度ボタンで×1／×4を切り替えます。一時停止・再生、時刻スクラバーも使えます。

両側の細菌図・細胞数・グラフは共通のframePresentationアダプターを通じて、同じSimResult.framesを読みます。図は初期32個、上限120個の模式表示です。上限時は実数の細胞数を併記します。グラフはlog10 NとKanR B。すべてのKanRグラフにB0の基準線があります。推定MIC、f、細胞内薬Aiも読み取れます。fはHill式の殺菌応答で、既に死亡した細胞の割合ではありません。

投薬後120分のClpXP完全阻害という仮定と、KanR低下から細胞数低下までの遅れを説明しています。終了時に両側のΔlog10と3-log到達判定が表示され、「結果とまとめへ」が有効になります。

0 cells/mL、Δlog10=−∞は、すべての注入クラスが1細胞/mL未満となってモデルから除外されたことを意味します。滅菌の実験的証明ではありません。生存クラスがない時の平均B・f・Aiの0表示も、この集計規約によるものです。MICは「生存クラスなし」と表示します。

## 5 — 結果とまとめ

5枚のカードで、最初に効かなかった理由、PVC、BinderとXB、ClpXP、再び効く可能性を振り返ります。中央のメッセージは、耐性原因タンパク質を取り除いて既存抗生物質の効果回復を目指すこと。直結分解タグの実証と設計アダプター・統合系の未実証を区別する注記、およびExp3プラトーの限界を表示します。

「もう一度遊ぶ」はストアを初期化してステージ1へ戻します。構成、MOI、シミュレーション、クイズ、用語閲覧履歴、再生状態は保持しません。

## 共通の操作

ヘッダーの「科学的根拠」、または最終画面の「科学的根拠を見る」でモーダルを開きます。実証／モデル予測の区別、簡略化と限界、params.tsから生成するパラメーター来歴表があります。「閉じる」で戻ります。用語チップはマウスを重ねると一行説明が現れ、クリックでも説明を表示します。

## 実際に確認したブラウザープレイ

最終のproduction buildを127.0.0.1:4174で配信し、既存のheadless ChromiumとPlaywrightで、マウスクリックによる1→2→3→4→5→「もう一度遊ぶ」を完走しました。全7スロットをクリック選択→配置で操作。wrong-rbpの実時間再生停止と修復を確認し、残り6種類はマウスでスクラバーを進め、該当段階での停止と戻る操作を確認しました。MOI両端、22秒の連続再生、比較の一時停止・時刻操作・×4再生、科学モーダル、初期化を確認しました。

観測テキストとPNGはplaythrough/に保存しています。observations.jsonのcompleted=true、errors=[]。ネットワーク要求はローカルのHTML・JS・CSSの3件のみでした。run.log末尾はPLAYTHROUGH PASSです。QA用scripts/playthrough.mjsは既存Playwrightを使用する補助スクリプトであり、ゲームの依存パッケージではありません。必要に応じSUNRISE_PLAYWRIGHT_MODULEとSUNRISE_CHROMIUMでローカルの実装・ブラウザーを指定できます。

## 以前の検証記録と残る限界

REVIEW2時点の記録：npm test=48/48、npm run validate=成功、npm run build=成功。1本の18時間計算の最終測定は187.0004msで400ms未満。オフラインnpm ciも成功しました。

数値検証の詳細はVALIDATION.md、モデルの前提・全パラメーターはMODEL.mdを参照してください。R10は15個のNtotセル中14個が補正された精度規則に合格し、Kan125/kcat .2516の1セルは入力B*の丸めを伝播しても不一致のまま、承認された既知の出典不一致としてテスト・文書に残しています。R11aの6定常値とノックダウン、R11bの4組の限界値は合格。丸めだけで許容される2セルは弱い証拠と明記しています。

未解決なのは、wiki内のj_req3/6と必要Ntot表の矛盾、K_mの単位ラベル、R10の1セル、R15の血清目標対（B=.0518でMIC=27.0855となり22未満を再現しない）、Exp3の高発現プラトー、Eq21の遊離／総KanRの曖昧さ、一定合成による定常期外挿です。パラメーター調整はしていません。設計アダプターと統合SUNRISEの実験的有効性は未確立です。

REVIEW2時点のブラウザー検証はheadless Chromiumのみ。ネイティブEdgeはツールから許可されず、Firefox・Safari・実際のGitHub Pages配信・実際の高校生による所要時間や学習効果は未確認です。スマートフォン・キーボード操作は対象外です。

## REVIEW3の画面変更

KanRが未処理の基準B0を超える時は、グラフ直下に、混雑で増殖と希釈が止まり一定合成が蓄積する定常期外挿の説明を表示します。推定MICにも「同上の外挿による」と注記します。耐性増強を示す実験結果ではありません。

再生中もクイズ・スライダー・ナビゲーションの要素を保持し、ステージを変えると先頭へ移動します。まとめの5枚のカードは、ステージ3と共通の各機構の図を使用します。科学的根拠では出典をモデル別に表示し、値は約4桁の有効数字に整えます（計算精度は不変）。

読み込み時にモジュールのエラーが起きた場合は、失敗の案内と再試行ボタンを表示します。

REVIEW3の再検証では、Chromium起動がspawn UNKNOWNとなり、EdgeのComputer Useも拒否されたため、新しい実ブラウザーでのステージ1〜5・誤配置停止・リセット・コールドロードは未検証です。以前の観察表は再観察結果ではありません。コールドロード不具合の原因は特定できておらず、bootstrapの失敗表示追加のみでR21の解決を確認したとは扱いません。
